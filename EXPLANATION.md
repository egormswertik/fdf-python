Данный документ создан для того, чтобы помочь детально разобраться в устройстве проекта, архитектурных решениях, математике изометрической проекции и каждой строчке написанного кода. Он послужит отличным конспектом для понимания и успешной защиты лабораторной работы перед преподавателем.

## 1. Введение: Что такое FdF?

**FdF** (сокращение от французского *Fil de Fer* — «проволочный каркас») — классическая задача компьютерной графики.

Суть задачи:
1. Дан текстовый файл карты высот формата `.fdf` (по сути — двумерная таблица чисел). Номер строки — это координата $y$, позиция числа в строке — координата $x$, а само значение числа — высота $z$ точки в трехмерном пространстве.
2. Программа должна прочитать этот файл, построить трехмерную модель сетки и спроецировать её на двухмерный экран монитора так, чтобы получился объемный изометрический проволочный каркас.
3. Каждое ребро сетки соединяет соседние точки по горизонтали и по вертикали.

## 3. Разбор каждого модуля

### 3.1. Модуль исключений: `fdf/exceptions.py`

В качественном Python-коде создают собственную иерархию ошибок:

```python
class FdfError(Exception):
    """Базовое исключение для всех ошибок библиотеки FdF."""

class MapFormatError(FdfError):
    """Исключение, возникающее при нарушении формата входной карты."""
```

**Зачем это нужно:**
- Наследование `MapFormatError` от `FdfError` позволяет в `main.py` одной строчкой `except FdfError as err:` перехватывать любые внутренние ошибки программы, отделяя их от системных ошибок вроде `OSError` (когда файл не найден на диске).
- Преподаватель видит четкую архитектуру обработки ошибок без перехвата «сырого» `except Exception`.

### 3.2. Модуль модели: `fdf/model.py`

Здесь определены базовые структуры данных: `Point` и `Map`.

#### Класс `Point`
```python
@dataclass(frozen=True, slots=True)
class Point:
    x: int
    y: int
    z: int
    color: str | None = None
```
- `@dataclass(frozen=True, slots=True)`:
  - `frozen=True` делает объект неизменяемым (immutable) и позволяет использовать его как ключ в словарях или элементах множеств (автоматически создается метод `__hash__`).
  - `slots=True` оптимизирует память и ускоряет доступ к полям за счет отказа от внутреннего словаря `__dict__` для каждого экземпляра.
  - Поле `color` хранит строку цвета в формате `"#RRGGBB"` (например, `"#FF0000"`) либо `None`, если цвет не был явно указан в файле карты.

#### Класс `Map`
```python
class Map:
    def __init__(self, width: int, height: int, points: list[Point]) -> None: ...
```
- Хранит ширину `width`, высоту `height` и плоский список всех точек `points`.
- Внутри также строится словарь `_grid: dict[tuple[int, int], Point]` для мгновенного доступа к точке по координатам `(x, y)` со сложностью $O(1)$.
- Реализует протокол итератора: `def __iter__(self)` позволяет обходить все точки карты простым циклом `for point in grid:`.
- **Ключевой метод `neighbors(point)`**:
  ```python
  def neighbors(self, point: Point) -> list[Point]:
      result: list[Point] = []
      # Сосед справа
      if (point.x + 1, point.y) in self._grid:
          result.append(self._grid[(point.x + 1, point.y)])
      # Сосед снизу
      if (point.x, point.y + 1) in self._grid:
          result.append(self._grid[(point.x, point.y + 1)])
      return result
  ```
  **Почему только справа и снизу?** Это ключевой момент из технического задания: *каждое ребро должно строиться ровно один раз*. Если бы мы брали всех четырёх соседей (вверх, вниз, влево, вправо), то линия между точками $A$ и $B$ рисовалась бы дважды: сначала из $A$ в $B$, а затем из $B$ в $A$. Беря только соседей справа и снизу, мы гарантируем, что каждое ребро будет нарисовано строго однократно!

### 3.3. Модуль парсера: `fdf/parser.py`

Функция `parse_map(file_path)` отвечает за чтение и строгую валидацию файла.

#### Алгоритм работы:
1. Открываем файл с явным указанием кодировки UTF-8.
2. Пропускаем пустые строки в конце файла (требование ТЗ: *пустые строки в конце файла игнорируются*).
3. Если файл пустой (или содержит только пробелы) — выбрасываем `MapFormatError("пустой файл карты")`.
4. Для каждой строки:
   - Разбиваем строку на токены по пробельным символам: `line.split()`.
   - Проверяем длину: все строки должны иметь одинаковое количество элементов. Если длина текущей строки отличается от первой строки — возбуждаем `MapFormatError(f"строка {line_no}: строки разной длины: ожидалось {expected_width} значений, получено {len(tokens)}")`.
   - Для каждого токена вызывается вспомогательная функция `_parse_token(token, line_no, col_no)`:
     - Число высоты и цвет могут быть разделены запятой: например, `20,0xFF0000` или просто `20`.
     - Проверяем, что $z$ является целым числом (`int(z_str)`). Если там буква или точка — ошибка с указанием номера строки и столбца: `строка X, колонка Y: 'значение' — не целое число`.
     - Если указан цвет, проверяем префикс `0x` или `0X`. В картах 42 ведущие нули могут опускаться (например, `0xFF` эквивалентно `0x0000FF`). Мы дополняем строку шестнадцатеричных цифр до 6 символов с помощью `.zfill(6)` и переводим в верхний регистр: `f"#{hex_digits.zfill(6).upper()}"`. Если код цвета невалиден — возбуждается ошибка формата.
5. Возвращаем готовый объект `Map(width, height, points)`.

### 3.4. Модуль проекции и камеры: `fdf/projection.py`

Это сердце математической части FdF.

#### Формулы изометрии
В трехмерном пространстве у точки координаты $(x, y, z)$. На экране монитора координат всего две: $(X, Y)$.

В задании заданы точные формулы изометрической проекции:
$$x' = (x - y) \cdot \cos(30^\circ)$$
$$y' = (x + y) \cdot \sin(30^\circ) - z \cdot z_{scale}$$
$$X = x' \cdot scale + offset_x$$
$$Y = y' \cdot scale + offset_y$$

**Почему высота $z$ вычитается?**
В компьютерной графике (и в Tkinter Canvas) ось $Y$ направлена **сверху вниз** (точка $(0, 0)$ находится в левом верхнем углу окна). Поэтому, чтобы положительная высота $z$ поднимала вершину вверх, мы должны уменьшать экранную координату $Y$ (то есть вычитать $z$).

#### Автоподгонка под размер окна: метод `Camera.fit(grid, width, height)`
Пользователь может открыть окно любого размера (800x600, 1920x1080 и т.д.), а карта может содержать как 25 точек, так и 10 000 точек. Как сделать так, чтобы каркас всегда красиво помещался в окно и был по центру?

Метод `fit` выполняет 4 шага:
1. Проецирует все точки карты с единичным масштабом $scale = 1$ и нулевым смещением $(0, 0)$.
2. Находит минимальные и максимальные значения получившихся координат: `min_x, max_x, min_y, max_y`.
3. Считает размер ограничивающего прямоугольника:
   $$bbox\_width = max\_x - min\_x$$
   $$bbox\_height = max\_y - min\_y$$
   Вычисляет итоговый масштаб с запасом 10% (коэффициент 0.9 для отступов от краев окна):
   $$scale = \min\left(\frac{width}{bbox\_width}, \frac{height}{bbox\_height}\right) \cdot 0.9$$
4. Вычисляет экранное смещение $offset_x, offset_y$, чтобы геометрический центр модели в точности совпал с центром окна $(width / 2, height / 2)$.

#### Бонусы камеры:
- `zoom_at(factor, cx, cy)`: масштабирование с фиксацией фокуса на курсоре мыши. Точка под курсором остаётся неподвижной, а окружающая сетка плавно приближается или удаляется.
- `height_color(z, z_min, z_max)` и `lerp_color`: расчет цвета по градиенту высоты. Низкие точки окрашиваются в синий цвет, средние — в зеленый и желтый, а пики гор — в ярко-красный.
- `isometric = False`: переключение на параллельную проекцию (вид строго сверху), где ребра образуют плоскую регулярную сетку.

### 3.5. Модуль графического интерфейса: `fdf/app.py`

Интерфейс построен на стандартной библиотеке `tkinter`:
- Не требует установки сторонних библиотек (работает везде, где есть Python с Tkinter).
- Виджет `tk.Canvas` используется для быстрого векторного рисования линий методом `create_line(x1, y1, x2, y2, fill=color)`.
- Обработчик `<Configure>` следит за изменением размеров окна пользователем и автоматически перерисовывает каркас с актуальным центрированием.
- Обработчики событий мыши и клавиатуры поддерживают интерактивное управление:
  - Колесо мыши и клавиши `+` / `-` — зум.
  - Левая кнопка мыши (Drag & Drop) и стрелочки — перемещение модели по холсту.
  - `Q` / `E` — вращение угла изометрии.
  - `Page Up` / `Page Down` — сжатие и растяжение по высоте ($z_{scale}$).
  - `P` или `Пробел` — переключение проекции (3D / 2D вид сверху).
  - `C` — включение/выключение градиента высот.
  - `R` — сброс камеры в исходное состояние.
  - `Esc` — быстрый выход из программы.
- Информационный оверлей (HUD) в левом верхнем углу выводит подсказки по управлению и текущие параметры проекции.

### 3.6. Точка входа: `main.py`

Файл `main.py` связывает аргументы командной строки с логикой программы:
- Проверяет длину `sys.argv`. Если аргумент не передан или их слишком много — выводит справку в `sys.stderr` и завершает процесс с **кодом возврата 2** (стандарт POSIX/Unix для синтаксических ошибок CLI).
- Загружает карту через `parse_map`.
  - Если возникла системная ошибка ввода-вывода (`OSError`, например файл не существует или нет прав на чтение) — выводит аккуратное сообщение в `sys.stderr` и завершает процесс с **кодом возврата 1**.
  - Если файл карты поврежден (`FdfError`) — выводит сообщение о нарушении формата карты в `sys.stderr` и завершает процесс с **кодом возврата 1**.
  - **Никаких страшных системных трейсбеков (`Traceback ...`) пользователю не показывается** — это строгое требование лабораторной работы.
- Создает экземпляр `App` и запускает цикл событий `app.run()`.

## 5. Ответы на частые вопросы преподавателя

### В: Почему класс `Point` сделан как `frozen dataclass`?
> **О:** Координаты точки сетки и её цвет являются фундаментальными значениями модели и не должны случайно измениться во время работы программы. `frozen=True` делает объект неизменяемым и автоматически генерирует для него метод хеширования `__hash__`, что позволяет безопасно хранить точки в множествах и словарях. А флаг `slots=True` существенно снижает потребление оперативной памяти за счет отказа от динамического словаря `__dict__`.

### В: Почему генератор соседей `neighbors()` возвращает только точки справа и снизу?
> **О:** В техническом задании зафиксировано правило: каждое ребро каркаса должно строиться ровно один раз. Если мы для каждой точки будем соединять её со всеми 4 соседями, каждое ребро продублируется дважды (из $A$ в $B$ и из $B$ в $A$). Ограничение соседей только направлением вправо (+x) и вниз (+y) гарантирует отсутствие дубликатов линий на холсте.

### В: Почему в формуле проекции высота $z$ вычитается, а не прибавляется?
> **О:** В компьютерных экранных координатах ось $Y$ направлена сверху вниз: нулевая отметка находится у верхнего края окна, а положительные значения спускаются к нижнему краю. Чтобы точка с положительной высотой $z$ визуально поднималась вверх к небу, её экранную координату $Y$ нужно уменьшать.

### В: Как работает метод `Camera.fit()`?
> **О:** Метод сначала виртуально проецирует все точки модели с базовым единичным масштабом. Затем находит крайние границы модели (`min_x, max_x, min_y, max_y`) и делит доступные размеры окна на габариты модели с запасом в 10% (коэффициент 0.9). Меньший из двух коэффициентов берется в качестве общего масштаба, чтобы модель вписалась целиком без искажения пропорций. В конце вычисляется смещение, совмещающее центр модели с центром окна.

### В: Почему `tkinter` импортируется только в `app.py`?
> **О:** Это архитектурное требование лабораторной работы по принципу разделения ответственности (Separation of Concerns). Модель данных (`model.py`), парсер (`parser.py`) и математические расчеты проекции (`projection.py`) представляют собой чистое ядро программы. Они не зависят от графической библиотеки и могут быть легко протестированы в консоли без создания графических окон, а также легко портированы на любой другой графический движок (Pygame, Qt или веб-рендерер).
